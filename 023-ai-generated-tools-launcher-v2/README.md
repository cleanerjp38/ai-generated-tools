# 023 AI Generated Tools Launcher v2

AI生成ツール30個プロジェクトの23個目。

これまでに開発したツールの中から、日常的に使いたいものを選び、Windows上から簡単に起動できるGUIランチャー。

以前開発した `009-ai-generated-tools-launcher` の新バージョンとして作成した。

## 1. 概要

PythonのTkinterを使用したデスクトップアプリケーション。

登録したツールをボタンのクリック、または数字キーで起動できる。

すべてのツールを登録するのではなく、実際に使いたいツールだけを登録する方針を採用した。

## 2. 主な機能

- 登録済みツールの一覧表示
- ボタンをクリックしてツールを起動
- 数字キーによるショートカット起動
- Webアプリを既定のブラウザで開く
- Python製GUIアプリを別プロセスで起動
- `tools.json` によるツール登録情報の管理
- 起動対象のファイルが存在しない場合のエラー表示
- Windowsショートカットからの起動

## 3. 登録ツール

| 番号 | ツール名 | 起動方式 | ショートカット |
|---|---|---|---|
| 012 | Idea Backlog Manager | Python GUI | 1 |
| 021 | Dice Roller Web | Webアプリ | 2 |
| 022 | Motivation Dog | Webアプリ | 3 |

ブラウザ拡張の001 YouTube Randomizerと005 Random Browser Lockは、今回のランチャーには登録していない。

## 4. 使用技術

| 技術 | 用途 |
|---|---|
| Python | ランチャー本体 |
| Tkinter | GUI画面 |
| JSON | ツール登録情報 |
| pathlib | ファイルパス管理 |
| subprocess | Python GUIの起動 |
| webbrowser | Webアプリの起動 |
| Git / GitHub | バージョン管理・公開 |

TkinterなどのPython標準ライブラリを使用しており、ランチャー本体には外部Pythonパッケージを必要としない。

ただし、起動先のツールには個別の実行環境や依存関係が必要になる場合がある。

## 5. ファイル構成

```text
023-ai-generated-tools-launcher-v2/
├── main.py
├── tools.json
└── README.md
```

### main.py

ランチャー本体。

`tools.json` を読み込み、登録されたツールの数に応じてボタンを生成する。

ボタンのクリックや数字キー入力を受け付け、ツールの種類に応じて起動処理を実行する。

### tools.json

登録するツールの情報を管理する設定ファイル。

各ツールのID、名前、種類、ファイルパス、説明を記録する。

### README.md

ツールの概要、使用方法、構成、注意事項などをまとめた説明書。

## 6. 起動方法

### 通常起動

PythonがインストールされたWindows環境で、リポジトリのルートディレクトリから以下を実行する。

```powershell
python 023-ai-generated-tools-launcher-v2/main.py
```

### Windowsショートカットから起動

`pythonw.exe` を使用したWindowsショートカットを作成すると、PowerShellを手動で開かずにランチャーを起動できる。

ショートカットのリンク先には、`pythonw.exe` と `main.py` の絶対パスを指定する。

```text
"<Pythonのインストール先>\pythonw.exe" "<リポジトリの保存先>\023-ai-generated-tools-launcher-v2\main.py"
```

実際のパスは使用するPCの環境に合わせて設定する。

## 7. ツールの登録方法

`tools.json` を編集することで、ランチャーに表示するツールを変更できる。

設定例：

```json
{
  "tools": [
    {
      "id": "012",
      "name": "Idea Backlog Manager",
      "type": "python-gui",
      "path": "012-idea-backlog-manager/main.py",
      "description": "開発アイデアを管理する"
    },
    {
      "id": "021",
      "name": "Dice Roller Web",
      "type": "web",
      "path": "021-dice-roller-web/index.html",
      "description": "ダイスを振る"
    },
    {
      "id": "022",
      "name": "Motivation Dog",
      "type": "web",
      "path": "022-motivation-dog/index.html",
      "description": "犬に励ましてもらう"
    }
  ]
}
```

`path` には、リポジトリのルートディレクトリからの相対パスを指定する。

対応する `type` は以下の2種類。

- `web`：HTMLファイルを既定のブラウザで開く
- `python-gui`：Python製GUIアプリを別プロセスで起動する

ツールの表示順は、JSON内の登録順に従う。

数字キーのショートカットは、先頭から1〜9番目までのツールに割り当てられる。

## 8. プログラムの動作

1. `main.py` を起動する。
2. `tools.json` から登録情報を読み込む。
3. Tkinterでランチャーのウィンドウを作成する。
4. 登録情報をもとにボタンを自動生成する。
5. ユーザーがボタンまたは数字キーでツールを選択する。
6. 指定されたファイルが存在するか確認する。
7. `type` に応じてブラウザまたはPythonプロセスで起動する。

ツールの登録情報と起動処理を分離しているため、対応形式のツールであれば、基本的に `main.py` を変更せず登録できる。

## 11. 注意事項・制限

- Windowsでの使用を想定している。
- PythonとTkinterが利用できる環境が必要。
- 起動先のツールがリポジトリ内に存在する必要がある。
- Webアプリは既定のブラウザで開く。
- ブラウザ拡張を直接操作する機能はない。
- ランチャーは起動先ツールの処理内容やデータ保存を管理しない。
- `pythonw.exe` を使用すると、コンソールにエラーが表示されない場合がある。問題の調査時には `python.exe` で起動する。

## 12. セキュリティ・プライバシー

ランチャー本体は外部APIや認証情報を必要としない。

ツールのパスは相対パスで管理し、個人のユーザー名やPC固有の絶対パスをソースコード・設定ファイルに記載しない。

ランチャー自身は個人情報を収集・送信しない。ただし、起動先のツールの動作については、それぞれのREADMEを参照する。

GitHubへの公開前には、秘密情報や個人情報、他のツールの作業データを誤ってコミットしないよう確認する。

## 13. 今回の学び

### データと処理の分離

ツールの登録情報を `tools.json` にまとめ、起動処理を `main.py` に分離した。

これにより、ツールを追加するたびにPythonコードを書き換える必要がなくなった。

### 異なるアプリケーションの連携

WebアプリとPython GUIという異なる形式のツールを、1つのランチャーから起動できるようにした。

### 必要な機能を選ぶこと

当初は22個のツールをまとめる構想だったが、実際に使いたいツールを選別し、3個に絞った。

すべてを統合することより、使いやすさとシンプルな構造を優先した。

### 既存ツールの再利用

既存の012・021・022を大きく改造せずに利用できた。

新しいツールを作る際に、既存のプログラムを組み合わせる設計も有効だと学んだ。
